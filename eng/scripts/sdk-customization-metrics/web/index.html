Customization overview

How many libraries carry handwritten customizations, and what kind.

What is counted?

Entry points are handwritten customization files found deterministically (Python _patch.py, Java customization scripts, C# non-generated source, JavaScript overlays, Go custom*.go). They link to the exact code but are not yet classified.

Customizations are individual, reviewed instances with a category (LRO, paging, …), explanation and pinned evidence. A library that has not been assessed shows N/A, never zero.

Reducible customizations

Customizations a generator or TypeSpec feature could provide in a general way, so future libraries that need the same behavior would not have to hand-write them.

How this is decided
  • Reducible: at least one library with the pattern was released or changed in the last 12 months, most reviewed instances are not tied to their service, and either it recurs in two or more services (Recurring) or most reviewers judged a generator could produce it (One service so far). Spec fix marks a pattern in one service across several languages.
  • Needs a human call: one service, and reviewers were mostly unsure whether a generator could produce it. Confirm or correct it in the library view.
  • Service-specific: most reviewed instances are tied to their service.
  • Dormant only: only in libraries untouched for over a year.

Collection diagnostics & technical details

Scan budgets are not collection failures. The collector captures up to 20 source/context files, 16 KB per file, and 100 KB per package. Files outside these budgets remain linked below, grouped separately from actual errors. Their contents were not analyzed. Coverage remains partial even when all eligible files fit.
