## Where handwritten code lives

Python has two customization patterns. A library uses one or both.

### 1. Inline customizations in `_patch.py`

The generator emits a `_patch.py` next to generated modules (package root, `models/`,
`operations/`, `aio/`, `aio/operations/`). Handwritten code goes there and is exported
through the module's `__all__`.

- **Count it** when `__all__` lists names, or the file defines classes/functions with real
  bodies that patch generated types (for example via `patch_sdk()`).
- **Do not count** the generated skeleton: an empty `__all__ = []` with a no-op
  `patch_sdk()`, or a file that only has the standard header and docstring.
- Each exported class or function that adds or changes behavior is a candidate instance.
  Overriding a generated client to add a method, wrapping an operation, or replacing a
  model are separate instances.

Example: [`azure-ai-agents` `_patch.py`](https://github.com/Azure/azure-sdk-for-python/blob/main/sdk/ai/azure-ai-agents/azure/ai/agents/_patch.py).

### 2. A handwritten library wrapping a generated folder

Some libraries put generated code in a folder whose name ends in `generated` (usually
`_generated/`) and write the public library around it. Then **everything outside the
generated folder** (excluding tests and samples) is handwritten customization code.

Example: [`azure-containerregistry`](https://github.com/Azure/azure-sdk-for-python/tree/main/sdk/containerregistry/azure-containerregistry/azure/containerregistry/_generated),
where `azure/containerregistry/_generated/` is generated and the rest of the package wraps it.

## Signals

| Signal                                                           | Meaning                                     |
| ---------------------------------------------------------------- | ------------------------------------------- |
| File named `_patch.py` with a non-empty `__all__`                | Inline customization                        |
| Folder named `*generated` (for example `_generated/`)            | Generated; files outside it are handwritten |
| Header `# Code generated by Microsoft (R) Python Code Generator` | Generated file                              |
| `_vendor.py`, `_serialization.py`, `_model_base.py`              | Generated support code, not customizations  |

## Not customizations

- Generated `_patch.py` skeletons.
- `__init__.py` files that only import from generated modules and `_patch.py`.
- `_version.py`, tests, samples, and dev requirements.
